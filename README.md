# TripMatch

毕业旅行拼团规划工具 Demo。发起人可以创建旅行、收集偏好并查看分组；参与人可以匿名提交预算、时间和目的地偏好，查看拼团状态并参与投票。

## 功能

- 发起人和参与人双角色流程
- 创建旅行需求卡
- 中国省份、城市两级选择
- 人均预算范围选择
- 邀请链接与参与偏好填写
- 按预算、时间和目的地自动分组
- 参与人拼团卡片与成员胶囊
- 目的地投票和成团结果
- “我的”活动分类记录
- 跨设备邀请、回传与组队结果发布（Supabase）
- 每人唯一用户 ID、邮箱验证码登录与登录态恢复
- 同一用户在同一活动中只保留一条参与记录
- 邀请链接强制参与人登录，不沿用分享者的当前会话
- 账号数据隔离：发起人、参与人和管理页面均按当前用户权限过滤
- 响应式移动端布局

## 自动分组规则

- 硬条件：共同可出行时间至少 3 天、预算相同或相邻、至少 1 个共同目的地。
- 人数：每组最多 8 人，少于 3 人标记为“待协调”，不会被静默删除。
- 评分：时间 40%、预算 25%、目的地 25%、出行风格 10%。
- 分组卡片展示匹配分、匹配等级、共同时间、共同目的地和待协调原因。
- 发起人点击“立即分组”生成预览，发布后参与人才能看到正式小组。

## 本地运行

项目不需要安装依赖，可以直接打开 `index.html`，或运行静态服务器：

```bash
python3 -m http.server 4173
```

然后访问 `http://127.0.0.1:4173`。

## 部署到 GitHub Pages

1. 在 GitHub 创建一个空仓库，例如 `tripmatch`。
2. 将本仓库推送到 GitHub 的 `main` 分支。
3. 打开仓库 `Settings > Pages`。
4. 在 `Build and deployment` 中选择 `GitHub Actions`。
5. 等待 `Deploy static site to GitHub Pages` 工作流完成。

网页地址通常为：

```text
https://<你的用户名>.github.io/tripmatch/
```

以后只要向 `main` 分支推送修改，原网页链接就会自动更新。

## 开启跨设备同步

1. 在 Supabase 新建项目。
2. 打开 SQL Editor，执行 `supabase.sql`。
3. 在 `config.js` 填入项目 URL 和 anon public key。
4. 在 `Authentication > Providers` 开启 Email，并使用邮箱验证码模板。
5. 在 `Authentication > URL Configuration` 中把 Site URL 设为正式网页地址，并把该地址加入 Redirect URLs。
6. 提交并推送到 GitHub，原 Pages 域名会自动更新。

建议在一个全新的 Supabase 项目中执行脚本。执行完成后，SQL Editor 中应能看到 `create_trip`、`submit_preference`、`get_user_dashboard`、`publish_groups` 和 `cast_vote` 等 RPC。所有浏览器请求都使用登录会话中的 `auth.uid()` 鉴权；兼容参数 `owner_token` 和 `participant_token` 不参与权限判断。

后端数据分为活动、参与偏好、分组版本、小组成员、投票和操作日志。发布新分组时，旧版本会标记为 `superseded` 而不会被删除；参与人只能读取自己的完整偏好、同组成员昵称和正式发布的小组，不能读取其他账号的完整资料。

`config.js` 中的 anon key 是 Supabase 设计为可公开使用的浏览器密钥；数据库表已开启 RLS，网页只通过限定的 RPC 方法访问数据。发起人管理令牌和参与人令牌保存在各自设备中，不进入邀请链接。

## 数据说明

登录方式整合：云端支持邮箱密码注册/登录及原有邮箱验证码；开启邮箱确认时，注册后须先确认邮件。密码仅交给 Supabase Auth，不写入应用表或表单草稿。本地新增手机号密码演示（PBKDF2 加盐摘要），仅限当前浏览器，不能替代服务器认证。旧昵称演示入口保留历史数据，不会自动合并到新手机号账号。未配置 Supabase 时不支持跨设备同步；短信登录尚未配置。

本次还修复了提交记录在跳转前绑定账号、重复提交复用记录 ID、跨设备管理不依赖本机令牌，以及云端读取分组时返回成员 ID。数据库脚本仍需在 Supabase 执行；静态网页更新不会自动更新数据库。

配置 Supabase 后，活动、参与偏好和已发布分组会跨设备同步；浏览器 `localStorage` 只保存当前设备的身份令牌和离线缓存。

登录后的数据归属规则：活动通过 `owner_user_id` 绑定发起人，参与记录通过 `user_id` 绑定参与人。刷新或重新打开会恢复登录态并重新读取账号数据；退出登录不会删除数据库记录。

账号隔离规则：发起人只能访问自己创建的活动及其参与数据；参与人只能访问自己的完整偏好和已发布小组的公开信息。前端路由校验只是体验层，正式云端必须同时依赖 Supabase `auth.uid()` 和 RPC/RLS 权限校验。

未配置 Supabase 时会自动进入本地演示模式：

- 本地体验账号按昵称恢复原用户 ID，仅用于单机演示。
- 正式云端通过邮箱验证码识别用户，同一账号跨设备恢复数据。

- 刷新页面后数据不会丢失。
- 不同浏览器、设备之间的数据不会同步。
- 清理浏览器网站数据会删除本地活动记录。

如需真实跨设备协作，需要接入后端数据库和身份系统。
